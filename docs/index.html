FIRST RUN

第一次使用：从项目根目录开始

这里按 v8.71 根目录 AGENTS.md 的实际启动约定编写。不要把网页当作 Runtime，也不必在首次启动就手动跑完整的 doctor。

照着顺序做

  1. 解压 v8.71 的正式 Workspace。保留 .agents/、AGENTS.md、project/ 等目录关系。一个 Workspace 对应一个项目。
  2. 在 Codex 中打开该项目根目录。新会话的首个业务请求应先按 AGENTS.md 完成最小初始化。
  3. 根据系统执行环境使用 Bootstrap。不同系统命令如下；如你的 Codex 会话已经按 AGENTS.md 执行，则无需重复运行。
    Windows：.agents\scripts\workspace_bootstrap.cmd
    macOS / Linux：sh .agents/scripts/workspace_bootstrap.sh
  4. 按真实返回状态处理项目准备。如果缺 Project Brief，就先整理项目事实；视觉类任务需要 Baseline 时依实际 preflight 补齐。别把所有视觉任务一律阻断。
  5. 选择第一个真实任务。例如直接生图、写一个 Visual Brief、或做 LOGO 方向。复制任务说明，提交给已有 Workspace 的 Codex 会话。
  6. 看实际成品与检查结果。文件、尺寸、文字和真实状态由 Workspace 验证；本网页不能代替它。

初始化返回这些状态，分别做什么？

needs_project_brief

项目事实未准备完整；按现有 material-index 和真实事实建立/刷新 Project Brief，再重新初始化。

needs_visual_baseline

当前视觉前置确实要求正式 Baseline；按 baseline_request 建立并发布，之后重试。

ready

可以按当前任务开始。baseline_pending 时是否补发，应以将要消费 Baseline 的路由判断。

blocked

读取机器返回的 reason，处理真正阻断的原因，不能手动假装已通过。

API Key 与初始化是两回事。 普通 Bootstrap 不检查 Key；真实生成在联网前检查，需要时运行相应系统的 api-check。若 api-check 报告凭据文件对当前执行身份不可读，请在你自己的账户终端里重新运行它：它会就地修复该文件的访问控制，且不读取也不改写 Key 值；在受限执行环境里重跑无法修复。仅在运行环境确实有问题时使用 runtime-check 或 runtime-repair，后者不修改源码。

新任务、继续、返修不是同一件事

状态判断由 Workspace 里的真实 Request 生命周期完成，网页不会直接创建 Request。

新需求新建 Request从 Intake 判断任务意图和专业入口
未完成回原 Request读取先前确认方向，继续下一步
已交付返修原 Request + 新 revision只修最早出错层，不重做整条链

任务做完了，去哪里找文件？

文件树来自 v8.71 的 Workspace Governance 契约。这里是目录结构示例，不表示你的项目已生成这些文件。

找到本次 Request

在 Codex 的项目根目录里打开 requests/，找到本次任务类型和对应需求标题。日期与序号由 Workspace 自动生成，不需要手填。

requests/
└── <request_type>/
    └── 【YYYYMMDD】NN-需求类型-标题/
        ├── request.md    本次需求与追加原话
        ├── state.json    实际生命周期状态
        ├── input/        原始输入证据
        ├── work/         中间研究、候选及门禁
        └── output/
            ├── manifest.json  已发布文件清单
            └── revisions/
                └── rNNN/     正式发布版本

仅成功发布后的用户交付才有正式 output；不要把 work/ 里的一张候选图当成最终完成。

拿到结果后怎么判断

  1. 确认本次 Request 对应你的目标，而不是其他任务。
  2. 打开正式文件核对角色、画面、文字、尺寸和格式。
  3. 需要可编辑 PSD，就实际打开检查图层和回合成。
  4. 不满意时在同一个会话告诉 Agent 保留什么、修改什么；不要手动改内部 state。
